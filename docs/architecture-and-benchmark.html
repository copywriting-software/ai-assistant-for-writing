Architecture, latency design, and local memory

System-wide writing tools feel sluggish when UI helpers and backend daemons duplicate timers or block on network calls. Here is how the Rust core and Swift helper divide responsibilities.

Two-process boundary

  • macos/MacHelper.swift handles CGEventTap key capture, AXUIElement snapshot reads, and the floating GhostPanel. It holds no completion state of its own and trims text before serializing JSON.
  • src/session.rs owns revision numbers, adaptive debounce timers, cancellation tokens, and ShowThinking / ShowGhost / HideGhost commands.
  • src/platform/mod.rs spawns grammar and rewrite tasks concurrently so long-running edits never stall keystroke handling or Esc cancellation.

Adaptive debounce and sliding-window cache

When you stop at a word boundary or punctuation mark, adaptive_debounce_ms shortens the wait to 70% of debounce_ms (down to 80 ms) so suggestions appear sooner. Mid-word pauses keep the full configured delay to avoid distracting popups while typing.

As documents grow past max_context_chars (600 characters), the context window shifts left. PrefixCache matches both direct prefix extensions and shifted suffix windows, serving remaining suggestion characters locally without another model call.

Local phrase memory and stats

MemoryStore persists accepted completions and request latency to a local JSON file (only after PrivacyGuard approves the context). Once you accept a completion for the same trailing context twice, future appearances are served locally in under 1 millisecond via fast_path_match.
