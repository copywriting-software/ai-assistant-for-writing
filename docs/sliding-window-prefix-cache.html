Why naive prefix caching breaks on long text

When a document grows past 600 characters, each new keystroke drops one character from the start of the tail window. A strict prefix check misses every time.

cargo test engine::tests::prefix_cache_handles_sliding_window_shift

How shifted suffix matching works

PrefixCache checks whether the new context window ends with a typed prefix of a cached suggestion preceded by at least 24 bytes of the cached tail, returning the remaining suffix locally.
